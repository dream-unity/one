# Confirmed constellation

`store.js` keeps two separate scopes. Device notes use one authoritative IndexedDB record: reads, consent/revision checks and writes share a `readwrite` transaction, and success resolves only after commit. Choosing **For this visit** creates an empty private in-memory graph. It never imports device notes, writes to IndexedDB/localStorage/sessionStorage/cookies, or broadcasts personal content. Reload, page departure and Exit close the store and discard visit notes and candidates. Ordinary navigation and Stop retain the visit graph.

The persisted v1 schema is unchanged. `validateDataset` validates device records strictly; `validateSessionDataset` separately validates volatile records with `storageEnabled: false`. Runtime scope is not a dataset or wire field. No migration, import, export, cloud synchronization or silent promotion is implemented.

`createMemoryStore({ onChange, onRevoke })` returns:

- `load()` → a cloned active dataset. An unavailable initial IndexedDB load returns an empty `unavailable` scope, with saving disabled until an explicit visit/device choice. A failed save remains an error with its exact candidate available; it never changes scope or claims success.
- `getStatus()` → `{ mode, savingEnabled, deviceAvailable, deviceError, switching }`. Modes are `device`, `session`, `off`, `unavailable`. Device consent can be disabled while device scope is loaded; use `savingEnabled` for save/share controls.
- `setMode('session' | 'device' | 'off', { consentEpoch, revision })` → the selected dataset. Session begins empty and leaves device notes intact. Device rereads the latest authoritative device graph, explicitly enables durable saving and resets sharing off; session content/drafts are discarded, never copied. Off clears/disables the active scope. Every switch advances both counters beyond the prior active scope; device return also advances beyond current persisted counters. A failed device choice preserves the visit graph.
- `setConsent({ storageEnabled, conversationUseEnabled }, { consentEpoch, revision })` → the committed active dataset. Sharing is independently opt-in in either saving scope. Session scope requires `storageEnabled: false`; switching to device requires explicit `setMode`. Sharing revocation retains visit notes. Disabling device storage deletes device notes and relationships. To end visit remembering use `setMode('off')`.
- `commitProposal(proposal, { consentEpoch, revision, authorship, signal })` → `{ dataset, record, before, duplicate, changed }`. User saves default to `authorship: 'user'`. AI saves require an opaque exact-confirmation receipt from the proposal controller.
- `deleteNode(id, { consentEpoch, revision, expectedRevision })` and `deleteEdge(...)` → the committed active dataset. Node deletion atomically removes incident edges.
- `clear({ consentEpoch, revision })` → clears active records and sharing. Session remains available for new visit notes; device saving is disabled with a durable tombstone.
- `clearDevice()` → atomically deletes the entire latest device graph and disables its scopes. When a visit is active its records remain untouched. Call this only for an explicitly confirmed device deletion, independent of the active visit's expected tuple.
- `selectContext(ids)` → `{ consentEpoch, revision, records }`, at most six explicit records and 2,500 aggregate Unicode characters/10,000 bytes. Edge endpoint notes are not implicitly included. The store itself makes no network calls.
- `subscribe(listener)` → unsubscribe; `close()` invalidates pending work, destroys the private graph/cache and releases the database/channel.

`onChange(dataset, detail)` reports current authoritative active state after the status is ready. Device broadcasts contain only schema version, revision and consent epoch; another tab rereads IndexedDB. Visit scope ignores device broadcasts and rereads current authority on explicit device return. `onRevoke({ pending: true, ... })` fires immediately on destructive/mode intent so the shell can cancel replay and proposals. It is not proof that deletion committed: display success only after the promise resolves. Callback reentrancy and late transaction completion cannot publish an older graph into a new scope. Operation-owned switch locks prevent an older completion from unlocking a newer choice.

`createMemoryController({ store, onPendingChange })` keeps one volatile AI candidate. `propose(proposal, { turnId, sharedIds, consentEpoch, revision, signal })` supplies exact review data; `confirm(proposalId, { turnId })` commits only that current candidate. `reject`, `invalidate` and `close` cancel confirmation-owned operations. The shell invalidates at new-turn, Stop, correction, navigation and conversation-clear boundaries. Targeted edits require currently shared IDs and revisions; candidates are never persisted.

`mountMemoryView(...)` renders authored notes, status choices, directed relationships, explicit context selection and exact AI before/after review. It returns `refresh`, `setProposal`, `getSelection`, `close`. The shell owns storage/sharing/deletion controls. Mode changes clear open drafts, selections and candidates so visit text cannot carry into the device editor. The optional `onConfirmProposal` must execute the owned confirmation and return its actual result.

Bounds remain 128 nodes (including archived notes) and 256 relationships, with identical field/Unicode/referential validation in both scopes. No audio, automatic biography extraction, transcript archive, exercise ingestion, personal state sent to Earth or cloud sync is implemented.

Validation: `node --test tests/memory-prototype.test.mjs`. Focused tests include transactional cancellation, device revocation, exact confirmations, bounds, native-adapter error classification, explicit visit CRUD/sharing, zero device access during visit operations, reload/Exit lifecycle, scope isolation, latest cross-tab authority, unchanged legacy data, failed/corrupt device choices, post-commit completion and reentrant switch ownership. Native browser/device acceptance is verified separately.
